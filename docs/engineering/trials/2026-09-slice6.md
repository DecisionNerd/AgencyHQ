6. **Verification timeout test matched unrelated host processes with `pgrep -f "sleep 30"`** (709154c; also on slice-5 at a40f262 — same root cause).

## Observations

- **Lead plan timeout**: P2's first `lead.plan` timed out at 270 s while three other plans ran concurrently; re-planned by operator command (succeeded in ~75 s). Plan timeout reason is not exposed in `/api/decisions` (gap, same family as the review pending-reason gap).
- **K4 plan parked pending_human**: Lead proposed `profileId: multi-repo-v2` for a single-repo item (no manifest sibling); the pending decision's violation reason is not exposed in `/api/decisions` (same gap). Consumer catalog narrowed to `node-pnpm-v2` by SQL; K4 re-planned.
- **P4 accept pending_human APPROVAL_REQUIRED**: diff touched only `test/parser/reject.test.ts`; the contract's `humanRequired.boundaries: [merge]` applied regardless of diff scope — by design (ADR-0006); reasons live only in the command result, not in `/api/decisions`.
- **K4 `lead.review` timed out** at task `maxDuration` (300 s, run_cmtt6ny3c, 21:30:11–21:35:12Z); retry :r1 failed within 25 s; decision `review:pending_human` at 21:35:37Z — the bounded Lead-failure path from Slice 4 held.
- **Lead reviews ran long during T3**: one EXECUTING >5 min at 21:35Z, three queued behind it.
- **`spike.echo` env probe** (run_cmtt67bvz): task process env carries the whole host environment (CLAUDE_*, CMUX_*, TRIGGER_*, PNPM_*, NODE_OPTIONS…); the adapters' allowlist strips it for children (HOME, PATH, USER, LOGNAME, SHELL, TERM, LANG, TMPDIR + GIT_* + AGENCYHQ_ATTEMPT_ID). PATH and HOME were identical between host and task process; the install difference was not isolated.
- **Shared ledger with browser-test seed**: the live coordinator shared its DATABASE_URL with the browser-test run; 33 seed attempts polluted the global slot count until ecc3cd6. Operational answer: a dedicated live database. Seed rows were left untouched.
- **K7 provider_unknown at 22:08Z**: the operator capacity row for `openai/gpt-5.6-terra` expired at 21:44Z; effective status became `unknown` (concurrency 1 — conservative stale handling); K7 skipped `provider_unknown`. The provider gate precedes the slot gate in `selectDispatch`.
- **Attempt status reuse**: `status='dispatched'` is set on each of the verify/review/accept dispatches and is left non-terminal when an item parks `pending_human`; the scheduler no longer depends on it (ecc3cd6), but the ledger still reads as if a worker were running (design debt).
