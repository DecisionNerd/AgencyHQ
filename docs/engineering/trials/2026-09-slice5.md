## Defect found by screenshot and fix

Screenshot `04` taken on `74bea12` showed "Pending integration · no timestamp" on the Integration card while the evidence panel showed "Outcome integrated / revision 5cbff2c" and the ledger recorded `completed`. The page also had no lifecycle/condition label. Root cause: the single-item view endpoint (`GET /api/work-items/:id/view`) did not forward `integrations` and `work_item_projects` rows to `buildReturnView`.

Fix commit `6ab2f2f` (`slice-5: single work-item view carries integration state and manifest; page shows lifecycle and condition`):
- `apps/coordinator/src/views/return-view.ts` — `buildReturnView` now accepts and forwards `integrations` and `manifest` arrays.
- `apps/coordinator/src/app.ts` — route handler for `GET /api/work-items/:id/view` now fetches and passes those rows.
- `apps/coordinator/src/views/overview-view.ts` — lifecycle and condition fields threaded through to the page header.

Screenshot `04` was retaken after the fix at 2026-09-08T15:34:19Z on `6ab2f2f`. It shows the Integration card and lifecycle line correctly.

## Rework after independent review (2026-09-08)

An independent review at `be841ff` found eight issues. Rework commit `84cdb08` (`slice-5 rework (coordinator, db): open-pending rule, persisted reasons, guards, authority CAS`) fixes them without a new live trial:

| Finding | Fix |
| --- | --- |
| T-4: `APPROVAL_VERSION_MISMATCH` inserted an `approval_mismatch` decision (not a resolving outcome) but the open-pending filter was not attempt-scoped, so the pending decision disappeared from the view | `approve.ts`: `approval_mismatch` correctly left as non-resolving; `pending.ts` `isOpenPending` now checks `attemptId` equality — only `approved`, `rejected`, `accepted`, `invalidated` resolve an attempt's pending decision. Covered by `control-plane-rework.test.ts` T-4 test, which calls `approveWorkItem` with a mismatched revision, then reads the decisions view: the pending decision stays open and an `approval_mismatch` row is confirmed in the database |
| T-5: `reject` and `invalidate_acceptance` dropped the `reason` field (no column existed) | Migration `0005_decision_reason.sql`: `ALTER TABLE decisions ADD COLUMN IF NOT EXISTS reason text`; `reject.ts` and `invalidate-acceptance.ts` persist the supplied reason |
| T-8: `set_main_effort` skipped the membership guard | `setMainEffort` db repo enforces membership; `campaign.ts` delegates to it and returns `not_a_member` when the work item does not belong to the campaign |
| T-9: `update_authority` had a lost-update race | `update-authority.ts`: `BEGIN` + `SELECT FOR UPDATE` on the project row; CAS `UPDATE … WHERE authority_version = $current`; under the row lock the second writer reads the committed new version and returns `version_not_increasing` (see U-6 correction in rework 2) |
| T-12: `reject` mutated the pending decision row | `reject.ts` appends a new `rejected` decision (pending row kept as history — R-017); the work item lifecycle is set to `halted` |
| T-13: initial authority version not in `authority_versions` | `update-authority.ts` backfills the pre-update version as history when `authority_versions` is empty for the project on first update |
| T-1/T-7: browser journeys race-prone; per-file counts wrong; stop proved "stopped" | Seeds per-journey items; spec table corrected; stop journey asserts "stopping" only (see table above) |
| T-6: decisions-page approve/reject had no confirm; work-item dialogs omitted project | Rework commit `2fee03d` (`slice-5 rework (web)`): all destructive actions show `ConfirmDialog`; approve/reject/invalidate name project, work item, and contract version |
