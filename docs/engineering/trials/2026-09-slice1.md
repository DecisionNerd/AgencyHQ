**Earlier failing runs and changes.**

The adapter's checkpoint commit used `git commit` without `--allow-empty`; when the

Also discovered in this item: the Trigger API reports CANCELED 22–38 ms after
`runs.cancel`, but the adapter's confirmation (survivors in run metadata) arrives

merely for final run status — see [Findings](#findings).

**Verdict.** PASS.

**Earlier failing runs and changes.**

Run trial-3 failed because survivor processes were found after the maxDuration stop:

```
EVIDENCE item3 finalStatus=TIMED_OUT
EVIDENCE item3 survivorScan=[71223,71289]
RESULT item=3 FAIL reason=survivorScan found survivors: [71223,71289]
```

When the Trigger CLI receives `maxDuration`, it SIGTERMs the task process immediately
and Node exits at once, leaving the abort listener no usable time to finish killing
the OpenCode process group. The fix (wave-1.5b) added a soft deadline in the adapter:
it stops the worker 15 s before `maxDuration` (with a minimum of 5 s), returns
outcome `timed_out` with the run reaching COMPLETED (not TIMED_OUT from Trigger), and
installs a SIGTERM hold so any in-flight kill completes before the process exits.
The hard `maxDuration` remains the backstop.

Also: `survivorScan` was updated to union `ps -E` environment marker matches with
command-line matches, because `ps -E` showed no environment for the live child process
in the trial environment.

## Findings

These findings arose from the trial and changed the adapter or the design
documentation.

1. **Late onCancel race.** A late `onCancel` callback returned before the
   abort-listener kill finished; Trigger then terminated the task process mid-kill,
   leaving survivors. Fix: late callers now `await` the in-flight stop promise
   (wave-1.5b). Affects: `trigger/src/tasks/worker-attempt.ts`.

2. **SIGTERM on maxDuration leaves no time for cleanup.** When the Trigger CLI
   SIGTERMs the task process on `maxDuration`, Node exits immediately; the abort
   listener has no usable time. Fix: the adapter now stops the worker 15 s before
   `maxDuration` (soft deadline), returns outcome `timed_out` with the run
   COMPLETED, and installs a SIGTERM hold to keep in-flight kills alive. The hard
   `maxDuration` remains the backstop (wave-1.5b). Affects:
   `trigger/src/tasks/worker-attempt.ts`, `docs/engineering/EXECUTION_MODEL.md`.

3. **API CANCELED precedes adapter cleanup.** The Trigger API reports CANCELED
   22–38 ms after `runs.cancel`, before the adapter has finished killing the process
   group and writing the stop record. The Coordinator "Confirm" step must wait for
   adapter evidence (survivors in run metadata, or `stop.ndjson` on disk), not only
   for a final run status. Affects: `docs/engineering/EXECUTION_MODEL.md`.

4. **Checkpoint ref requires --allow-empty.** Without `--allow-empty`, a `git commit`
   on an empty staged index produces no commit and no ref. Fix: all checkpoint commits
   use `--allow-empty` (wave-1.5b). Affects: `trigger/src/lib/git.ts`.

5. **Run metadata frozen once final.** Trigger run metadata cannot be updated once
   the run is in a final state. The adapter writes `<runDir>/stop.ndjson` as the
   durable on-disk stop record (fields: `abort_signal`, `on_cancel_entered`,
   `soft_deadline`, `stop_start`, `killed`, `checkpoint`, `stop_done`). On the host
   profile this file is the confirmation source. Affects:
   `docs/engineering/EXECUTION_MODEL.md`.

6. **Filesystem isolation is advisory on the host profile.** Shell redirects from the
   worker created `../escape.txt` (worktree parent) and `/tmp/agencyhq-escape.txt`.
   In-worktree out-of-contract writes (`secrets/leak.txt`) were quarantined and
   reverted by the adapter's path-classification check. Out-of-worktree escape paths
   are reachable because the host profile carries no filesystem boundary. This is
   declared advisory in `ARCHITECTURE.md`'s enforcement table; contracts that require
   filesystem isolation are rejected at dispatch on this profile.

7. **task: "deny" produces no denial event.** OpenCode does not offer the `task` tool
   at all under `task: "deny"`; no tool_use event for that tool fires. Absence of
   `task` tool_use events is the evidence. Affects: trial harness item 4c assertion.

## Gaps and advisory boundaries

- **Filesystem escape (out-of-worktree):** Shell redirects can write outside the
  worktree and to `/tmp`. The host profile declares filesystem isolation advisory.
  Contracts requiring isolation are rejected at dispatch; the container profile adds
  a container filesystem boundary.
- **gh CLI token reachable from a worker shell:** The `gh` CLI keyring token remains
  reachable from a worker shell via `bash`. The `deny` rule on `gh *` applies; the
  container profile removes credential access entirely.
- **Run metadata frozen once final:** Trigger run metadata cannot be updated once the
  run is in a final state. The adapter's `stop.ndjson` file in the run directory is
  the durable record for the host profile.

## Verdict on ADR-0005 and ADR-0007

The isolation and recovery contract held on the host profile within its declared
advisory boundaries. ADR-0005 (adopt self-hosted Trigger.dev as execution runtime) is
**not superseded**; the trial evidence qualifies it. ADR-0007 (workers produce
proposals, not effects) is **not superseded**; push was blocked and no worker-caused
external effect reached a shared ref.
